# Phase 4.3 — Tools are contracts

> **Principle:** *Your tool schemas are your public API. Version them like one.*
> **Time:** ~10 minutes
> **Files touched:** 1 — `catalog-server/src/tools/compare-monsters.ts` (rename a Tool, then put it back)

## Why

The gateway publishes a manifest. Claude Code has learned that manifest at handshake time. The LLM in turn has learned which tool names map to which intent.

What happens when you change a name?

In a REST world this is a versioning conversation: you bump the path, you add a deprecation header, you publish a migration window, you keep both endpoints alive for two release cycles. **MCP tool descriptions are a public API too — they just don't feel like one yet.** This phase makes the contract-break visible.

You'll break it, observe what happens, name the four kinds of breaking change, then restore the original.

## Files touched

```
catalog-server/src/tools/compare-monsters.ts   ← rename a Tool, then revert
```

You will NOT touch the gateway. The whole point of 4.3 is that breakage propagates *through* the gateway from a child server.

## Steps

### Step 1 — Break a contract live (3 min)

Open `catalog-server/src/tools/compare-monsters.ts`. Find the line that says:

```typescript
server.registerTool(
  "compare_monsters",
  {
```

Change it to:

```typescript
server.registerTool(
  "pit_monsters",
  {
```

Save.

Restart the **gateway** (Ctrl-C its terminal if running, then `bun --hot run gateway/src/server.ts`) — or just restart Claude Code, which will re-spawn it. Restart matters because `mergeManifests()` runs once at gateway startup.

In Claude Code, run `/mcp`. You should now see `catalog.pit_monsters` listed instead of `catalog.compare_monsters`.

### Step 2 — Re-ask the canonical prompt (2 min)

> **"Who wins between Thunderclaw and Aquafrost?"**

What happens depends on Claude Code's session memory:

- **If it's the same Claude Code session that learned the old name:** it may try `catalog.compare_monsters` first, get a tool-not-found error, then either re-discover or give up. You'll see this in the audit log:
  ```jsonl
  {"...","name":"compare_monsters","status":"error",...}
  {"...","name":"pit_monsters","status":"ok",...}
  ```
- **If it's a fresh session:** it picks `pit_monsters` from the manifest and the call succeeds first try.

**Either way, the rename was a breaking change you made unilaterally.** No version bump. No deprecation window. In a real fleet of agents this would break every active session that had cached the old name.

### Step 3 — Try it yourself (2 min)

Each pair: pick **a different** catalog tool and rename it. For example:

- `search_monsters_by_category` → `find_monsters_in_category`
- `list_categories` → `enumerate_categories`
- `get_monster_details` → `fetch_monster`

Restart the gateway. Re-run a prompt that would have used the old name. Watch the LLM react.

### Step 4 — Name the four kinds of breaking change (2 min)

Project France slide 211. There are four:

1. **Renaming a tool** (just did)
2. **Removing a parameter** — input becomes invalid for callers that included it
3. **Tightening an input schema** — what used to validate doesn't (e.g., `string` → `string().min(1)`)
4. **Loosening an output schema** — what callers parsed they can no longer rely on (e.g., a field becomes nullable)

For each: ask yourself *"would my agent fleet survive this if I deployed it on a Friday?"* If the answer is "I'd need to coordinate with N teams first" — it's a breaking change.

### Step 5 — Restore + the right way to evolve (1 min)

Revert the rename:

```typescript
server.registerTool(
  "compare_monsters",
  {
```

Save. Restart gateway.

The right way to evolve, instead:

```typescript
// Keep the old name as a deprecated alias for the migration window:
server.registerTool(
  "compare_monsters",
  {
    description:
      "[DEPRECATED — use `pit_monsters` instead] Compare two monsters head-to-head...",
    inputSchema: { ... },
  },
  async (args) => actualHandler(args),
);

server.registerTool(
  "pit_monsters",
  {
    description: "Compare two monsters head-to-head...",
    inputSchema: { ... },
  },
  async (args) => actualHandler(args),
);
```

Both names route to the same handler. Agents that learned the old name keep working; new code uses the new name. Remove the alias after your slowest agent has been re-deployed.

## Verify

`/mcp` shows `catalog.compare_monsters` again. The canonical battle prompt works.

## Observe

The audit log from your rename experiment is itself the lesson. Two adjacent lines, one error and one ok, separated by ~milliseconds — the LLM "lost" a request because you changed a name. That's what a contract break looks like in MCP.

## What this state delivers

A typed understanding of MCP-as-contract. You changed a tool name; the agent broke; you fixed it.

**Principle landed:** *Tool schemas are public APIs. Rename costs.*

**Don't surprise the agent.**
