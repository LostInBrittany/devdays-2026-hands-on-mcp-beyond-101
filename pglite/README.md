# pglite — the workshop's shared database

> Boot this once at the start of the day. Every PG-touching step (02, 03, …) connects to it.

## What it is

A single PGlite instance — Postgres compiled to WASM, running in-process under Bun — fronted by the Postgres wire protocol on `127.0.0.1:5432`. Seeded with the full [RAGmonsters](https://github.com/LostInBrittany/RAGmonsters) dataset: **30 monsters across 9 normalized tables** (categories, subcategories, monsters, questworlds_stats, keywords, abilities, flaws, augments, hindrances).

No Docker. No PG install. No cloud. One Bun process.

## Why it lives at the repo root and not inside a step

Steps 02 and 03 both connect to this database — *same data, different MCP servers* is the v1 → v2 narrative. Putting PGlite inside step-02 would (a) duplicate it for step-03 and (b) expose `db/seed.sql` to whatever agent participants launch inside step-02 (which lets the LLM short-circuit MCP by just reading the file). Hoisting PGlite to the repo root fixes both.

## Boot it

```bash
cd pglite
bun install        # only the first time
bun run start:pg
```

You should see:

```
[pg] booting PGlite at .../pglite/pgdata
[pg] applying seed from .../pglite/db/seed.sql
[pg] seeded — monsters table has 30 row(s)
[pg] PGLiteSocketServer listening on 127.0.0.1:5432
[pg] connect with:  postgres://postgres@127.0.0.1:5432/postgres
```

**Leave this terminal running for the rest of the day.** Ctrl-C kills the database; restarting re-applies the seed from scratch.

## Connect from any step

The connection string is fixed:

```
postgres://postgres:any@127.0.0.1:5432/postgres?sslmode=disable
```

Notes:
- `?sslmode=disable` — pglite-socket doesn't speak SSL negotiation
- `:any` — pglite-socket fakes auth but requires *some* non-empty password; `any` is the convention

Each step's `.mcp.json` already points at this URL — no per-step config needed.

## Single-connection caveat

PGlite is single-connection. The MCP server holds the slot, so you can't open `psql` to inspect simultaneously. Practical consequence: **close any prior Claude Code session before starting a new one in a different step** — a stale session from step-02 will block step-03 from connecting.

## Files

```
pglite/
├── package.json     ← only @electric-sql/pglite + pglite-socket
├── bunfig.toml      ← minimumReleaseAge = 864000 (Shai-Hulud defense)
├── tsconfig.json
├── .gitignore       ← pgdata/, node_modules/
├── README.md        ← you are here
├── db/
│   └── seed.sql     ← ~150 KB autogenerated RAGmonsters seed
└── scripts/
    ├── start-pg.ts  ← boots PGlite + socket on :5432, applies seed.sql
    └── build-seed.ts  ← prep-time tool: regenerates db/seed.sql from
                         ../RAGmonsters/postgresql/ (talk-source-only;
                         not for workshop participants)
```

`db/seed.sql` is committed. `scripts/build-seed.ts` is a prep-time tool that depends on the parent `../RAGmonsters/postgresql/` folder, which only exists in the talk-source repo — participants don't run it.

## Resetting state

Destroyed the schema with the Prompt 4 bypass? Want a clean slate?

```bash
# Ctrl-C the start:pg terminal, then:
rm -rf pgdata/
bun run start:pg
```

`pgdata/` is regenerated from `db/seed.sql` on boot. The seed itself is idempotent (drops every table before recreating), so just restarting `start:pg` also resets — `rm -rf pgdata/` is for "I want zero PGlite state, including the WAL".
